# VideRAG

YouTube 영상을 **선택한 것만** 자막 기반으로 분석해서, 그 영상에게 직접 질문할 수 있게 해주는 서비스를 만듭니다.

## 무엇을 하나요

여러 YouTube 채널·재생목록의 **메타데이터(제목·설명)만 먼저 수집**하고, 사용자가 폴더 안에서 명시적으로 고른 영상만 자막을 내려받아 RAG(검색 증강 생성) 챗봇으로 분석합니다. "일단 다 긁어와서 나중에 찾기"가 아니라 "필요한 영상만 골라서 대화하기"에 초점을 맞췄습니다.

- **폴더 중심 구조** — 관심 주제별로 폴더를 만들고, 그 안에 영상을 직접 추가하거나 채널·재생목록을 연결해 수집 후보를 추천받습니다.
- **선택적 분석** — 사용자가 고르지 않은 영상은 음성 다운로드·STT·임베딩을 전혀 실행하지 않습니다. 비용과 저장공간을 필요한 만큼만 씁니다.
- **근거 있는 답변** — RAG 답변의 모든 근거는 영상 ID, 시작/끝 타임스탬프, 실제 재생 위치로 바로 이동하는 링크를 함께 제공합니다.
- **투명한 추천 기준** — 영상 추천은 제목·설명 임베딩 기반이라는 걸 응답에 명시합니다. "영상 내용까지 확인했다"고 과장하지 않습니다.

## 대표 프로젝트

### [video-rag-mvp](https://github.com/VideRAG/video-rag-mvp)

FastAPI 기반 백엔드(API 서버 + Worker)와 React(Vite, shadcn/ui) 프론트엔드로 구성된 MVP입니다.

- **API와 Worker는 DB로만 대화합니다.** Worker가 FastAPI에 직접 콜백을 보내지 않고, `jobs`/`videos` 테이블을 통해서만 상태를 주고받습니다 — 나중에 큐를 Redis/PostgreSQL로 바꿔도 이 경계는 그대로 유지됩니다.
- **분석 진행 상황은 SSE로 실시간 스트리밍**되고, 실패 원인은 항상 `error_message`/`analysis_error`에 남습니다.
- **계정 없는 익명 작업공간** 구조라 로그인 없이 바로 시작할 수 있고, 8자리 코드로 다른 브라우저와 데이터를 공유할 수 있습니다.
- 현재는 로컬 SQLite로 동작하며, PostgreSQL + pgvector 기반 운영 환경(NCP)으로 전환하는 걸 목표로 하고 있습니다.

## 기술 스택

`FastAPI` · `SQLite → PostgreSQL/pgvector` · `React` · `Vite` · `TanStack Query` · `shadcn/ui` · `Docker`
